# 参考样例拆解：双格科普漫画


*[English](format-analysis.md)*

分析对象：72 张真实样例，来自 4 个不同账号/系列
（Jerry 老鼠俗语系列、章鱼哥楼盘科普系列、章鱼哥性格对比系列、白猫女士拍照/楼盘系列）。
这份文档记录本工具的版式常量是怎么来的。

## 一、共同的版式骨架

所有样例的结构完全一致：

```
┌──────────────────────────┐  ← 做旧纸张底色，四周有 3~5% 留白
│ ┌──────────────────────┐ │
│ │      ╭──────────╮    │ │  ← 标题横幅：圆角矩形，暖黄/米色底，
│ │      │ 短标题    │    │ │     深色细描边，居中，黑色粗黑体
│ │      ╰──────────╯    │ │
│ │                      │ │  ← 画面：插画铺满整格，主体居中偏下
│ │        [插画]         │ │
│ └──────────────────────┘ │
│ ┌──────────────────────┐ │  ← 第二格，结构完全相同
│ │      ╭──────────╮    │ │
│ │      │ 短标题    │    │ │
│ │      ╰──────────╯    │ │
│ │        [插画]         │ │
│ └──────────────────────┘ │
│      ♪ 抖音号：XXXXXX      │  ← 页脚水印，白字带暗描边，居中
└──────────────────────────┘
```

| 元素 | 观察值 | 本工具默认值 |
|---|---|---|
| 画布比例 | 3:4（样例原图 1792×2400、1080×1440） | `1792×2400` |
| 四周留白 | 约 2.5%~3.5% 边长 | `margin: 46`（设计单位） |
| 两格间距 | 约 1.5% 高度 | `gap: 26`（设计单位） |
| 画格边框 | 深褐/黑，4~6px | `border: 5`，`#2B2622` |
| 横幅底色 | 暖黄 `#E9C877` / 米褐 `#D9C3A0` | `#E9C877` |
| 横幅位置 | 画格顶部往下约 3% | `top: 34`（设计单位） |
| 横幅宽度 | 随文字长度变化，最宽约画格 88% | `max_width: 0.88` |
| 横幅高度 | 紧贴文字，文字视觉居中 | 按文字**墨迹**算，上下各留 `pad_y: 34` |
| 标题字体 | 粗黑体（思源黑 Heavy 一类），纯黑 | 自动找系统中文粗体；字体集合里挑**简体中文**那一个 |
| 标题字号 | 一整套一个字号 | 整套统一：取最长那句需要的字号 |
| 标题字数 | **5~14 字**，绝大多数 6~10 字 | `validate` 按真实排版量宽度；超过 18 个字宽判错 |
| 页脚 | 音符图标 + "抖音号：xxx" | `footer: 128`；颜色 `auto`（浅色纸用墨色字 —— 原先的白字对米色纸只有 1.06~1.28:1） |
| 质感 | 半调网点 + 纸张颗粒 + 暗角 + 做旧边缘 | `texture` 四个开关；颗粒是零均值的，纯黑纯白不动 |

设计单位是 1440×1920 画布上的像素，所有常量按实际画布更紧的那一边等比缩放
（默认 1792×2400 时 ×1.244）。

## 二、内容规律（比版式更重要）

1. **一条作品 = 一个主题 = 10~14 个并列信息点**。6 张图 × 2 格 = 12 个点。
   - 楼盘系列：湾 / 岸 / 馆 / 府 / 城 / 山 … 一格一个词条。
   - 性格系列：稳重的人 / 共情能力差 … 一格一个特征，正反交替。
   - 俗语系列：「女婿本是墙外树」「再粗不是顶梁柱」… 上下两格是一副对子。

2. **句式在整套里高度工整**。要么全是 `"X"是YYY`，要么全是 `N个字的短语`。
   这种排比感是观众一路刷到底的直接原因。

3. **主角固定**。同一系列里永远是同一个角色（Jerry / 章鱼哥 / 白猫女士），
   跨图长相、服装、配饰完全一致 —— 这就是个人 IP 的做法，也是本工具
   `--character` 功能要解决的问题。

4. **画面直译文案**，不玩隐喻。说"临水而居"就画阳台外面是河。
   观众扫一眼就要懂，不能让人思考。

5. **场景有变化但世界观统一**：室内/室外、白天/夜晚、远景/近景交替出现，
   但画风、色调、角色造型不变。

## 三、两个关键的工程决策

**① 文字不让模型画，由本地字体渲染。**
样例里的中文横幅笔画干净、字重统一，是后期贴上去的。AI 画中文容易缺笔画、串字，
一套 6 张只要糊一张就得重跑。本地渲染还有个好处：改文案不用重新生图，
`dig render --script script.json --skip-images` 几秒钟重排完。
所以每条生图提示词里都硬写了"画面中绝对不要出现任何文字"。

**② 底图按画格尺寸单独生成，而不是一次生成整页。**
让模型一次画出"两格 + 横幅 + 页脚"的完整页面，构图不可控、文字必糊。
本工具给每一格按画格自己的比例单独要一张略大（1.15×）的图，再在本地贴合铺满，
构图稳定，重画某一格也不影响其它格（`dig reroll --panel N`）。

## 四、抖音发布的几个硬限制

- 图文作品最多 35 张，推荐 3:4 或 9:16；本工具默认 3:4。
- App 界面会遮住底部约 200~260px（文案区和按钮），重要内容别放最下面。
  本工具把页脚水印放在这个区域上沿，正好卡住安全线。
- 首图决定点击率，所以 `prompt_builder.cover_hint()` 对第 1 格额外加了强调。
- 每个作品目录里都有一张 `preview.jpg`：整套排在一张图上，再把第 1 张放进示意手机，
  用红色虚线框出界面大致会挡住的位置（右侧互动栏、底部作者/文案区）。
  位置是示意，以 App 实际为准。
